## 4. Problemas encontrados

### Críticos (impedem funcionamento hoje)

1. **Worker não está instalado nesta VPS.** `systemctl --user list-timers` lista
   0 timers, `~/.config/systemd/user/` não tem nenhuma unit `job-scraper-*` e
   **`~/botasaurus-env` não existe** — todos os `.service` apontam para
   `%h/botasaurus-env/bin/python`. Há um `.venv/` na raiz do repo (requests e bs4
   ok), mas os units não o usam. Consequência: nada coleta desde a reinstalação.
2. **Programathor nunca roda pela UI.** O conector está registrado e em
   `BULK_SOURCES`, mas `web/src/routes/searches.tsx` (`ALL_SOURCES`) não oferece a
   opção. Como `run_source` só roda fontes presentes em `search_profiles.sources`,
   a fonte só é usada se alguém editar o array direto no banco.
3. **Correção da Gupy não commitada.** O endpoint antigo morreu; a versão nova
   funciona (testado), mas está só no working tree. Commitá-la é pré‑requisito.

### Altos (perda silenciosa de dados)

4. **Vagas sem descrição nunca recebem score.** `jobs_needing_enrichment` exige
   `description_text not null`. Se o `fetch_detail` do LinkedIn/Programathor
   tomar 429 no meio, o resto do lote é gravado sem descrição — e como só se busca
   detalhe de ids *novos*, ele nunca é refeito. A vaga fica no feed para sempre
   sem score. Falta um "re-detalhar pendentes" (ou enriquecer só com título +
   `raw` como fallback).
5. **Quebra de fonte é invisível.** O caso Gupy (404 global) virou
   `scrape_runs.status='blocked'`/`error` — sem alerta. E uma mudança de seletor
   (LinkedIn/Programathor) devolve 0 cards com status **`ok`**. Precisa de alarme
   para "N rodadas seguidas com `jobs_found=0` ou não-ok".
6. **`scrape_requests` pode travar em `running`.** Se o processo morrer entre o
   claim e o finish (timeout do systemd, OOM, reboot), não há reaper; o botão
   "Buscar agora" mostra eternamente "rodando".
7. **Erro de rede no `search()` de LinkedIn/Gupy/Careerjet não tem retry.** Um
   `ConnectionError`/timeout sobe como exceção genérica → `status='error'` e a
   fonte perde a rodada inteira (6h). Só o Programathor trata
   `RequestException`.

### Médios

8. **`description_text` recebe HTML cru** na Gupy e na Careerjet (só o
   Programathor/LinkedIn extraem texto). O LLM recebe tags no prompt, o que gasta
   token dos 6000 chars de orçamento.
9. **`jobs_needing_match` não escala:** baixa todos os `job_id` já pontuados e
   pede `limit + len(scored_ids)` linhas. Com alguns milhares de vagas vira uma
   query enorme a cada 2h. Melhor um RPC/view `not exists`.
10. **Race no `_attach_to_canonicals`** (read‑modify‑write de `sources`/`alt_urls`):
    `collect` e `queue` rodando juntos podem perder um badge. Baixo impacto, mas um
    `UPDATE ... SET sources = array(select distinct unnest(sources || $1))` via RPC
    resolve.
11. **Gupy: `skills` sempre vazio** no endpoint novo; `PAGE_SIZE=50 × MAX_PAGES=10`
    não serve para nada porque `run.py` passa `limit=50` (uma página só).
12. **Vagas nunca expiram.** Não há `closed_at`/TTL; o feed acumula vagas
    encerradas. Gupy traz `applicationDeadline` e o Programathor `validThrough` —
    já estão no `raw`, só não são usados.
13. **Dependências não declaradas/pinadas.** Worker não tem `requirements.txt`
    (foi justamente o que tornou a reinstalação da VPS dolorosa); o `web/package.json`
    usa `"latest"` em 8 pacotes TanStack.
14. **Zero testes.** Parsers HTML (LinkedIn, Programathor) e `dedup.py` são os
    candidatos óbvios a testes com fixtures HTML salvas.
15. **Docs defasadas:** README/SETUP mandam aplicar só 0001+0002 (faltam 0003 e
    0004, sem as quais o feed quebra — a view `jobs_feed` não existe); não citam
    Programathor; SETUP diz que `ai.match` não tem timer (já tem, via
    `MATCH_USER_ID`) e lista 4 timers em vez de 5.

## 5. Sugestões priorizadas

### P0 — voltar a funcionar (≈ 1–2 h)
- Commitar a migração da Gupy.
- Recriar o ambiente: `worker/requirements.txt` (requests, beautifulsoup4,
  botasaurus opcional) e apontar os units para um venv do projeto
  (`%h/projects/job-scraper/.venv`) em vez do `~/botasaurus-env` compartilhado.
- Reinstalar os 5 timers (incluindo `match`, que o SETUP esquece).
- Adicionar Programathor em `ALL_SOURCES` do `searches.tsx`.
- Atualizar README/SETUP (migrations 0003/0004, Programathor, 5 timers).

### P1 — notificação (o elo que falta no pipeline)
- **Digest no Telegram** (bot próprio, `sendMessage` via HTTP, 1 arquivo
  `worker/notify.py` + timer): vagas com `score ≥ X` ainda não notificadas.
  Exige coluna `notified_at` em `job_matches`. Alternativa: e‑mail diário via
  Supabase/Resend.
- **Alerta de saúde das fontes** no mesmo canal: fonte com 2+ rodadas seguidas
  `error`/`blocked` (exceto google_jobs) ou `jobs_found=0`.

### P2 — robustez
- Retry com backoff para erros de rede em todos os conectores (helper comum em
  `connectors/base.py`, ex.: `get_with_retry`).
- Re-detalhar vagas sem descrição (`description_text is null` e
  `first_seen_at > now()-7d`), ou fallback de enrich com título + `raw`.
- Reaper de `scrape_requests` em `running` há > 30 min.
- `html_to_text()` em `sanitize.py` usado por todos os conectores.
- Fixtures + `pytest` para os parsers e para `dedup.py`.
- Pinar dependências do web.

### P3 — novas fontes BR (por custo/benefício)

| Fonte | Por quê | Como (a verificar antes de implementar) | Esforço |
|---|---|---|---|
| **Vagas.com.br** | Grande, generalista, forte fora de TI | HTML server‑side em `/vagas-de-<termo>` | médio |
| **InfoJobs BR** | Volume grande, CLT | HTML; checar anti-bot | médio |
| **Catho** | Maior board BR | SPA com API interna; parte do conteúdo exige login — validar ToS antes | alto |
| **Remotar** | Só remoto, BR, nicho TI | site leve, provável API JSON | baixo |
| **GeekHunter / Trampos.co** | TI e criativo BR | HTML/API pública | baixo–médio |
| **Greenhouse / Lever / Ashby (boards de empresas)** | APIs JSON públicas e oficiais (`boards-api.greenhouse.io/v1/boards/<empresa>/jobs`), zero anti-bot; cobre fintechs/startups BR que não usam Gupy (Nubank, Creditas, QuintoAndar...) | lista curada de empresas no `.env`/tabela | baixo |
| **Solides / Kenoby / Recrutei (ATS BR)** | Mesma lógica da Gupy: muitas empresas médias publicam só ali | career pages por empresa; checar se há busca global | médio |
| **BNE / SINE (Emprega Brasil)** | Vagas públicas/operacionais, se o público‑alvo ampliar | API do governo, verificar | médio |
| **Remotive / We Work Remotely / RemoteOK** | Remoto internacional pagando em USD | APIs/RSS públicos | baixo |

Recomendação: começar por **Greenhouse/Lever/Ashby** (APIs oficiais, estáveis,
alto sinal) e **Remotar** — baixo esforço e sem risco de bloqueio — antes de
encarar Vagas/InfoJobs/Catho, que são raspagem HTML com anti-bot provável.

### P4 — filtros e qualidade do feed
- **Filtros negativos** no `search_profile` (excluir termos: "estágio", "Java",
  empresa X) aplicados no worker antes de gravar.
- **Faixa salarial** e **tipo de contrato** (CLT/PJ) como filtros no feed — os
  dados já existem em `job_enrichments`.
- **Recência** ("últimos 7 dias") usando `posted_at`.
- **Expirar vagas** usando `applicationDeadline`/`validThrough` e um
  `HEAD`/re-check periódico da URL.
- Usar os campos declarados (Programathor `seniority_label`/`contract_label`,
  LinkedIn `criteria`) como verdade sobre a inferência do LLM no `_clean()`.
